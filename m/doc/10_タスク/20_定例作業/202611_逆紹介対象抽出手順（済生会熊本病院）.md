# 逆紹介対象抽出手順（済生会熊本病院 / tenant 11）

> **対象範囲と前提**
> * **対象病院**：済生会熊本病院（テナントID：`11` / `t011`、医療機関ID参考：`438211911`）
> * 本手順は **済生会熊本病院専用** です。新東京病院（`t135`）および鳥取県立中央病院（Python未対応・DBeaverでのクエリ実行）とは手順が異なります。
> * **使用リポジトリ**：[outpatient-ops](https://github.com/MedUpInc/outpatient-ops)（各自のローカル作業ディレクトリで実行）
> * **処理の安全性**：本パイプラインは BigQuery の入力テーブル・ビューを参照（Read）するのみで、本番DBや BigQuery 上の元レコードの作成・更新・削除は行いません。
> * **dbt 実行**：両診療科とも期間指定集計（`patient_summary_by_period_repo`）で `outpatient_ef` 等を直接集計しており、dbt ビューには依存しないため、月次実行前の `just dbt-run` 等は不要です。

## 作業概要・スケジュール・関連環境

### 業務上の位置づけとスケジュール
高度急性期病院（済生会熊本病院）の診療実績（外来EF）と翌月予約データを突合し、近隣クリニック等へ逆紹介可能な候補患者リスト（Excel）を月次で抽出・作成する作業です。

| 項目 | 内容・タイミング |
| :--- | :--- |
| **データ受領依頼** | 毎月 **20日頃** までに病院側へデータ送付を依頼（Googleカレンダーで20日にアラート管理。未着時は催促） |
| **抽出作業の実施** | 20日の翌週（概ね毎月 **24〜25日頃〜月末**） |
| **提出フロー** | 作成した Excel ファイルを Google Drive の提出先フォルダへ格納し、**CS（カスタマーサクセス）担当者** へ連携（CS経由で病院へ送付） |

### 対象診療科と処理内容
| 診療科 | 実装スクリプト | 主な処理内容 |
| :--- | :--- | :--- |
| **泌尿器科** | `src/pipeline/tenants/t011/urology.py` | 泌尿器科の候補を医師・疾患名キーワード・医療資源カテゴリ・併科なし（`total_specialties_visited == 1`）・受診回数上限で抽出し、**抗がん剤および手術予定を除外**した上で、出力対象医師（`output_doctor_names`）ごとに医師別の Excel を出力する。 |
| **呼吸器外科** | `src/pipeline/tenants/t011/respiratory_surgery.py` | 任意期間の患者サマリーを診療科（YAML上は `呼吸器科`）・医療資源カテゴリ（CT/MRI または 検査）・対象医師・併科なし（`total_specialties_visited == 1`）・受診回数上限で抽出し、**退院から一定年数（2年）以上経過した患者**（基準日は実行日 `date.today()`）に絞り込んだ上で外来予約データと結合し、Excel を出力する。（※手術予定除外は行わない） |

### 関連環境・接続先
| ツール・基盤 | 接続先・補足 |
| :--- | :--- |
| **foro 管理ツール（foro core admin / MIS管理画面 / `admin-web`）** | 本番：https://admin-web.medup-core-service.com <br>済生会熊本「外来EF」タブ：https://admin-web.medup-core-service.com/foro-core/tenants/11?tab=outpatientEF <br>※Basic認証は 1Password（「foro管理ツール(Basic認証)」）で管理。DBにユーザー登録が必要。 |
| **BigQuery** | プロジェクト：`medup-foro`<br>主要データセット：`dpc_patient_records_prd`（外来EF・医師マスタ等）、`foro_prd`（紹介・DPCマスタ等）、`mis_prd`（医療機関マスタ等）、`others` |
| **Google Drive** | 病院が Box にアップロードしたファイルは `data-integration` 経由でセキュリティ管理された Google Drive のテナント別フォルダへコピーされ、Data Ops の振り分け後に `受領データ` フォルダへ移動される。<br>・受領データ確認フォルダ（全体）：https://drive.google.com/drive/u/0/folders/1pyo8eIEPpCZl3bQIntUx7PmWeAM5-g-B <br>・済生会熊本（tenant 11）用フォルダ：https://drive.google.com/drive/u/0/folders/1srhiPrDiCBbXWVYa4YtuBKq5Bw8hdiRW <br>・結果ファイル格納先（提出先）：https://drive.google.com/drive/u/0/folders/19ppu985HAQ0-nUPOewUsq_9penq0DfeI |

## 0. 初回セットアップ（初回のみ）

ローカル環境で初めて `outpatient-ops` を実行する前に、以下を準備します。

1. **依存パッケージのインストール**（Python 3.13+ / `uv`）
   ```bash
   uv sync
   ```
2. **環境変数ファイル（`.env`）の作成**
   リポジトリルートに `.env` を作成し、以下の4項目を設定します（`BQ_LOCATION` は既定値 `asia-northeast1`）。
   ```dotenv
   GCP_PROJECT=medup-foro
   BQ_FORO_DATASET=foro_prd
   BQ_MIS_DATASET=mis_prd
   BQ_DPC_PATIENTS_DATASET=dpc_patient_records_prd
   ```
3. **GCP 認証（ADC）**
   ```bash
   gcloud auth application-default login
   ```
4. **医師マスタの参照先確認**
   `src/bigquery/models/dpc.py` の `DoctorMasterT011.__tablename__`（143行目）は `"sk-kumamoto_doctor_master"`（Google Sheets 外部テーブル）が設定されています。外部テーブルの閲覧権限がない場合は、`"sk-kumamoto_doctor_master_snapshot"` へ変更してください（詳細は「実行時の注意・トラブルシューティング」参照）。

## 1. 必要なデータが揃っているか確認する

抽出を実行する前に、対象月のデータがすべて揃っているか以下の順番で確認します。

1. **Google Drive**：受領ファイルが格納されていること
2. **foro 管理ツール（foro core admin / MIS管理画面）**：外来EFがテーブルに投入済みであること
3. **BigQuery**：対象月の日付までデータが格納されていること

### 揃えるデータと対象月のルール
実行月を **$M$** とした場合、必要なデータと対象期間は以下の通りです。

| データ種別 | 対象期間 | 備考 |
| :--- | :--- | :--- |
| **外来EF（`Eg_`）** | 前月（$M-1$ 月）の末日まで | Eファイル＝診療明細情報。**入院データ（入院EF等）は見ない。** |
| **外来予約CSV** | 来月（$M+1$ 月）分 | 泌尿器科・呼吸器外科の**両方**で使用 |
| **手術予約CSV** | 来月（$M+1$ 月）分 | **泌尿器科のみ**で使用 |

* **対象月の具体例**：
  * `2026-10` 実行の場合：外来EFは `2026-09-30` まで、予約ファイルは `202611` 分
  * `2026-11` 実行の場合：外来EFは `2026-10-31` まで、予約ファイルは `202612` 分
* **中断条件（厳守）**：
  * 外来EFが対象月まで揃っていなければ、**予約CSVが揃っていても抽出しない**。
  * 予約CSVが無ければ、手順2「予約CSVを配置する」に進まない。

### 1-1. 受領ファイルの確認（Google Drive）
* 済生会熊本（tenant 11）用の Google Drive フォルダ（https://drive.google.com/drive/u/0/folders/1srhiPrDiCBbXWVYa4YtuBKq5Bw8hdiRW ）および受領データ確認フォルダ（https://drive.google.com/drive/u/0/folders/1pyo8eIEPpCZl3bQIntUx7PmWeAM5-g-B ）を確認します。
* 外来EFのファイル名は **`Eg_`** で始まります。
* 予約CSV（外来予約・手術予約）も同 Google Drive からダウンロードし、ローカルリポジトリの `data/11/` に配置します（詳細は手順2）。

### 1-2. テーブル投入状況の確認（foro 管理ツール）
* 本番の foro 管理ツールにある済生会熊本の **「外来EF」タブ**（https://admin-web.medup-core-service.com/foro-core/tenants/11?tab=outpatientEF ／裏側のテーブル：`medup_foro_outpatient_ef_importing_logs`）および **「データ受領/投入状況一覧」画面** で対象月が投入済みであることを確認します。
* Google Drive にファイルがあっても、管理画面上で対象月が未登録（未投入）であれば抽出を行いません。
* ※管理画面上だけでは「病院から未着」なのか「受領済みだが Data Ops 側で未投入」なのか判別できないため、必ず手順 1-1 の Google Drive 確認とセットで判断してください。

### 1-3. BigQuery での対象月データ格納確認
BigQuery に確認クエリを実行し、対象月の末日までデータが欠損なく入っているか確認します。
※ `bq query` 実行時に認証エラーが出る場合は、先に以下のコマンドで再認証してください。

```bash
gcloud auth application-default login
```

以下の確認クエリの日付を、**その回の前月と対象月**に読み替えて実行します（下記は `2026-10` 実行・対象月 `2026-09` の例）。

```sql
SELECT
  MAX(IF(action_detail_number = 0, outpatient_date.value, NULL)) AS max_e_date,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-08-01' AND DATE '2026-08-31') AS prev_e_rows,
  COUNTIF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30') AS month_e_rows,
  COUNT(DISTINCT IF(action_detail_number = 0 AND outpatient_date.value BETWEEN DATE '2026-09-01' AND DATE '2026-09-30', outpatient_date.value, NULL)) AS month_e_days
FROM `medup-foro.dpc_patient_records_prd.outpatient_ef`
WHERE tenant_id = 11
  AND data_type != 'SY';
```

**確認基準（すべてを満たすこと）**：
* `max_e_date`（最大受診日）が **対象月の末日以降** であること
* `month_e_rows`（対象月のE行件数）が `prev_e_rows`（前月のE行件数）と **同じ桁数** であること
* `month_e_days`（受診日数）が **対象月の日数ぶん** 存在すること

データが無い・不足している場合は、**CS経由で病院側へデータ提供を要求（催促）** します。

## 2. 予約CSVを配置する

Google Drive からダウンロードした予約月（$M+1$ 月）のファイルを、ローカルの `outpatient-ops` リポジトリ内 **`data/11/`** ディレクトリに配置します。

* `外来予約情報YYYYMM.csv`（泌尿器科・呼吸器外科の両方で使用）
* `手術予約情報YYYYMM.csv`（泌尿器科のみで使用）

**配置時の注意点**：
* 文字コードは **`cp932`** です。
* **ファイル名の年月（`YYYYMM`）とファイル中身のデータ対象月が一致していること**を確認してください。月が違うファイルを使うと行数が変わり、抽出結果の件数も誤った値になります。

## 3. YAML設定ファイルのパスと期間を更新する

以下の2つの YAML ファイルを編集します。

* `src/pipeline/tenants/t011/urology.yaml`（泌尿器科）
* `src/pipeline/tenants/t011/respiratory_surgery.yaml`（呼吸器外科）

**更新項目**：
1. **`appointment_csv`**：両方の YAML ファイルで、手順2で配置した `外来予約情報YYYYMM.csv` のパスに更新します。
   * ※リポジトリの初期状態に個人環境の絶対パス（`/Users/...`）が記載されている場合は、`data/11/外来予約情報YYYYMM.csv` 等の相対パス（または自身のローカルパス）へ書き換えてください。
2. **`surgery_csv`**：泌尿器科（`urology.yaml`）のみ、手順2で配置した `手術予約情報YYYYMM.csv` のパスに更新します（同様に個人環境の絶対パスが残っていれば書き換え）。
3. **`start_date` / `end_date`**：手順1で格納確認した対象月末までの **直近12か月間** に設定します。
   * 例：`2026-09` 実行（対象月 `2026-08`） → `2025-09-01` 〜 `2026-08-31`
   * 例：`2026-10` 実行（対象月 `2026-09`） → `2025-10-01` 〜 `2026-09-30`
   * 例：`2026-11` 実行（対象月 `2026-10`） → `2025-11-01` 〜 `2026-10-31`
4. **`output_path`**：
   * **泌尿器科（`urology.yaml`）**：親ディレクトリ（`outputs/11/`）のみ参照されるため、月次の変更は不要です。
   * **呼吸器外科（`respiratory_surgery.yaml`）**：指定パスの末尾に `_<実行日>` が自動付与されます。出力ファイル名に予約月番号を含める運用（例：`..._10.xlsx` → `..._10_2026-09-25.xlsx`）の場合は、対象月に合わせて更新してください。

### ログおよび出力内容のチェックポイント
* **「外来予約」の行数確認**：
  * ログで最初に見る数値は「外来予約」の行数です。これは YAML が指した CSV ファイルの行数そのものであるため、想定と異なる場合はファイルの取り違えを疑ってください。
* **呼吸器外科の対象医師コード数**：
  * 対象医師コードは `2件 / 3名` になることがあります。医師マスタに名前が一致しない医師が存在するためですが、予約枠の出力側には医師名が残る仕様となっているため問題ありません。
* **前月データとの乖離確認**：
  * 抽出結果の件数が前月と比較して大きく乖離している場合は、**診療報酬改定に伴うレセプトコード変更等**の影響がないか疑い、調査を行ってください。

## 実行時の注意・トラブルシューティング

* **医師マスタの参照先テーブル名と権限**
  * `src/bigquery/models/dpc.py` の `DoctorMasterT011.__tablename__`（143行目）は `"sk-kumamoto_doctor_master"` を参照しています。
  * 元の外部テーブルは Google Drive 側の権限がないと読み取れないため、権限エラーが発生する場合は 143行目を **`"sk-kumamoto_doctor_master_snapshot"`**（アンダースコア区切り）へ変更してください。
  * ※ハイフン付きの `sk-kumamoto_doctor_master-snapshot` は存在しません。
* **Polars 変換時のエラー対処**
  * 患者サマリーや紹介データを Polars の DataFrame に変換する際、先頭行の日付が空（NULL）だとスキーマ推論に失敗して落ちることがあります。
  * 発生した場合は、以下の該当箇所で `pl.DataFrame(..., infer_schema_length=None)` を指定して全行から推論させてください（抽出件数は変わりません）。
    * `src/pipeline/tenants/t011/urology.py`：133行目（患者サマリー）、193行目（紹介データ）
    * `src/pipeline/tenants/t011/respiratory_surgery.py`：108行目（患者サマリー）、159行目（紹介データ）

### 用語補足
* **逆紹介**：高度急性期病院に通院している患者のうち状態が安定した方などを、近隣のクリニック等へ紹介して戻す仕組み。
* **外来EF**：入院していない外来患者の診療記録（レセプト＝治療実績データ）。入院EFとはレイアウト・中身が異なる。
  * **Eファイル**：診療明細情報（外来適正化では主に外来のEファイル等を参照する）。
  * **Fファイル**：薬剤や特定器材などの行為明細（DPCの保険点数算出に使用される詳細データ）。
