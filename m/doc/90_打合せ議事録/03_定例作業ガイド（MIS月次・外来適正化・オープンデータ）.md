# 定例作業ガイド（MIS月次・外来適正化・オープンデータ）

---

## 1. オープンデータ取り込みの全体像

メダップで扱うオープンデータは以下の3種類が存在し、定期取り込みの仕組みがあるのは「医科・歯科」と「ナビイ」の2種類である（一般公開データの収集は、厚労省CSV取り込み・医療情報ネットスクレイピングを含め定期運用されている）。

| データ種別 | 取得・更新方法 | 定期取り込み | 更新頻度・備考 |
| :--- | :--- | :---: | :--- |
| **厚生局の医科・歯科指定データ** | 月次公開。Data Ops担当が手動で取得・一部加工し、管理ツール（`admin-web`）からインポートして **MIS** 本番を更新。 | あり（手動＋ツール） | 毎月1回（詳細は「2. MIS 月次更新作業」参照） |
| **ナビイ（navii / 医療情報ネット）** | Excel/CSVでの公開形式がないため**スクレイピング**で取得。`data-management-api` 等のスクレイピング機能が自動実行しDBへ反映。 | あり（自動） | **毎週金曜日**に自動実行（`tmp_ref_naviis` 経由で `ref_naviis` へ反映） |
| **介護サービス情報公表システムデータ** | 当初は定期更新を想定しておらず**未自動化**。 | なし | 半年に1回（6月分が7月、12月分が1月2日）公開されるため、本来は更新が必要という認識。 |

## 2. 定例作業①：MIS 医科・歯科マスタ月次更新

### 作業概要
* **作業内容**：MIS 医科・歯科マスタの月次更新
* **所要時間**：約2時間
* **元データの格納先**：厚生局から取得したデータは **Google Drive** に格納している。
  * ファイル名例：`新規施設一覧_〇〇県_20201220.xlsx`
* **診療科のマッピング対応**：
  * 病院ごとに独自に命名される診療科名称について、システム上でどの検索カテゴリに分類するかは **手動で対応** している（管理ツールの「診療科」タブ / `department_mappings` 等で紐付け）。

### 実施スケジュール
| 項目 | タイミング・方針 |
| :--- | :--- |
| **厚生局のデータ公開** | 毎月 10日頃 |
| **作業実施タイミング** | 毎月 24日〜25日頃 |
| **デッドライン** | 明確な期限は設けていないが、顧客（病院側）には「月末頃」と案内している |

### 運用上の補足・判断が難しいケース
* **事業承継の判別**：
  * 元データに **旧機関コード** が記載されている場合は、「事業承継」であることが判別できる。
* **病院の名称変更（課題ケース）**：
  * 名称変更があった場合、データ上だけでは「単なる名称変更」なのか「閉院して新規開院した」のかの区別がつかない（厚生局への届け出方法に依存するため）。
  * **対応**：システム上で重複一覧が出力されるため、別途内容を確認し、統合（名寄せ・クレンジング）作業を行う必要がある。
* **住所変更・移転（課題ケース）**：
  * 住所変更や施設移転がある場合も同様に、同一施設かどうかの判断が難しい。

## 3. 定例作業②：foro 逆紹介（外来適正化）月次データ抽出

### 作業概要と代行の背景
* **目的**：高度急性期病院に通院している患者に対し、別の医療機関（近隣クリニック等）への通院を案内する（＝逆紹介する）ための **候補患者リストを月次で作成** する。
* **Data Ops側で代行している背景**：
  * 大病院では月間の予約患者数が数千人に及ぶため、病院側で手作業により逆紹介候補を絞り込むのが困難。
  * 本来はプロダクト拡張のため病院側で一覧を作れるのが理想だが、現状は**抽出条件を病院側とすり合わせた上で、実際のCSV作成をメダップ（Data Ops側）が代行**している。
* **作業フロー**：
  1. 病院側から診療実績データ（外来EF）および翌月の予約データ（外来予約CSV・手術予約CSV）を提供してもらう。
  2. 診療実績データをもとに用意されたクエリ／Pythonパイプラインを実行し、翌月の予約データと突合して「来月の逆紹介候補リスト（作業リストのサジェスト）」を抽出する。
  3. 作成した外来適正化（最適化）用のファイルを、開発・Data Ops側から **CS（カスタマーサクセス）担当者へ渡し、CS経由で顧客（病院）へ送付** する（※現在は手作業で実施。CSはこれを元にコンサルティング資料等も作成する）。

### 実施スケジュール
| 項目 | タイミング・管理方法 |
| :--- | :--- |
| **データ受領依頼** | 毎月 20日頃までに送付してもらうよう病院側へ依頼 |
| **アラート管理** | 毎月 20日にアラート設定（Googleカレンダーで予定日を管理）。未着時は催促アラートを出す |
| **リスト抽出** | 20日の翌週（概ね毎月24〜25日頃〜月末）に逆紹介リストの抽出を実施 |

### 対象3病院の状況比較

| 病院名 | テナントID | 医療機関ID（参考） | 現在の運用・自動化状況 |
| :--- | :---: | :---: | :--- |
| **済生会熊本病院** | `T011` | `438211911` | **定例稼働中・Python自動化済み**（`outpatient-ops` リポジトリ） |
| **新東京病院** | `T135` | — | **定例稼働中・Python自動化済み**（`outpatient-ops` リポジトリ） |
| **鳥取県立中央病院** | — | — | **8月頃開始・一部稼働中／Python未対応**（現在は山田氏がDBeaverでクエリ実行しスプレッドシート出力） |

### 鳥取県立中央病院の抽出条件（直近1年実績ベース）
* 10月分までの実績をもとに、12月の予約リストから対象者を抽出する（1回のクエリでCSV出力）。
* 対象診療科は **整形外科・脳神経外科・泌尿器科** の3科。現在は **脳神経外科のみ稼働（条件変更の再確認中）** であり、整形外科・泌尿器科は現場でシミュレーション中。
* **整形外科の抽出・除外条件**：
  * **基本対象**：直近1年間の外来実績があり、**最大行為**が「処置・手術・注射」以下（＝過去1年間に入院がなく、退院から1年以上経過している）の患者。
  * **主な除外**：CT・MRIを受診した患者、ギプス・脱臼（期内の非観血的整復等）の患者、すでに逆紹介済みの患者。
* **脳神経外科の抽出・除外条件（より複雑）**：
  * **基本対象**：単純MRIフォローの患者。
  * **主な除外**：**併科**（他の診療科にもかかっている患者）、悪性新生物（悪性腫瘍）、血管内手術を実施した患者、造影MRI、てんかん、くも膜下出血など、病院側で最後まで責任を持って診る必要がある患者（細かなレセプト電算コードや病名で除外）。

### 済生会熊本・新東京病院のPython実行フロー
* **使用リポジトリ**：`outpatient-ops`（`src/pipeline/tenants/` 配下に `T011`、`T135` のディレクトリを配置）。
* **実行手順**：
  1. 病院から受領した予約CSV等のファイルをローカルにダウンロードする。
  2. 該当テナントの **YAML設定ファイル**（対象日付やファイルパス指定）を書き換える。
  3. 本番環境（BigQuery / DB等）への接続設定を行った上で、Pythonパイプラインを実行して逆紹介候補CSVを出力する。
* 鳥取県立中央病院についても、抽出条件が確定次第、同様に `outpatient-ops` へPythonスクリプトとして組み込み・共通化する予定。

### 毎月20日のデータ到着確認・受領チェック手順
#### 必要なデータと外来EFファイルの仕様
1. **前月までの外来EFデータ**（病院のレセプト＝治療実績データ）
   * 入院EFと外来EFではレイアウトや中身が異なる。
   * **Eファイル**：診療明細情報（今回の外来適正化プロダクトでは、来院不要な患者を特定する目的で主に外来のEファイル等を投入・参照する）。
   * **Fファイル**：薬剤や特定器材などの行為明細（DPCの保険点数算出に使用される詳細データ）。
2. **翌月分の外来予約CSV**
3. **翌月分の手術予約CSV**

#### 確認手順（STEP 1〜3）
* **STEP 1：本番管理画面（`admin-web` / foro Core Admin）での投入確認**
  * 対象テナント（例：済生会熊本）の **「外来EF」タブ** を開き、前月分が登録済みか確認する（テーブル：`medup_foro_outpatient_ef_importing_logs`）。
  * *参考事例*：9月分のデータは10月21日に登録済み。11月17日時点では10月分が未投入。
  * **注意点**：管理画面上だけでは「病院からまだ届いていない」のか「届いているがData Ops側で未投入」なのか判別できない。
* **STEP 2：Google Drive での原本受領確認**
  * セキュリティ管理された Google Drive のテナント別ディレクトリ（テナントIDと病院名で作成）を確認し、受領データ（外来E/Fファイル、外来予約CSV、手術予約CSV）が届いているかチェックする。
  * *参考事例*：済生会熊本の前回外来Eファイルは10月16日に到着。
* **STEP 3：未着時の催促**
  * **毎月20日**になっても必要データが届いていない場合は、病院側へ確認・催促を行うようアラートを出す。

### 抽出結果の確認ポイント
* 基本は用意されたクエリをそのまま実行する想定だが、**診療報酬改定に伴うコード変更等**があるとクエリの修正が必要になる。
* 抽出結果が前月データと大きく乖離している場合は、報酬改定等の影響を疑って調査を行う。
