# 保守業務の期待値・Data Opsの課題と重複データ対応 議事録

## 1. 保守業務全般について（案件参画における期待値）

### 期待されるアプローチ
* 運用の定例作業やマスタ管理について、「自動化させたい」「効率化したい」という現場の要望に対し、主体的にアプローチ・改善を進めていくことが期待されている。

### ドメイン理解の重要性と自律的な対応
* **ドメイン理解の必要性**：
  * 実際のプログラム改修や保守対応には、医療ドメインおよびシステム仕様・機能の深い理解が不可欠である（例：6月の診療報酬改定に伴うマスタ反映漏れの調査など）。
* **自律的な課題発見とアウトプット**：
  * 現在は非エンジニアの山田氏がマネジメントを担っていることもあり、保守領域は半ば放置状態に近い課題がある。
  * 指示待ちではなく、自ら問題点を見つけて対応・アウトプットを出せる自律的な動きを強く求めている。

## 2. 保守運用および Data Ops チームの現状と課題

### Data Ops チームの業務概要
* **主な役割**：顧客（病院）から受領したデータの投入保守作業や、データクレンジング（施設の名寄せ）を担当している（※社内ナレッジより補足：5名体制・計3人月以上の工数で手作業の定例運用を実施中）。
* **タスク管理**：**Asana** を使用して、重複医療機関データなどのチケット管理を行っている。

### マスタ登録作業における自動化の難しさ
* 厚生労働省（厚生局）のホームページから公開データを取得し、正規化・マスタ（MIS）登録を行う一連の作業は、現状すべて手作業で実施している。
* 原本データが正規化されていないことや、個別のケースごとに「人の判断」が介在するポイントが多いため、完全な自動化が難しい状況にある。

### メダップのサービス特性とクレンジング業務の位置づけ
* **強みと課題のジレンマ**：
  * 他社の医療SaaSが行わない「手作業でのデータクレンジング」や「マスタとの丁寧な突合」を行っている点がメダップの強みである一方、その運用負荷やデータ不整合がチャーンレート（解約率）に影響を与えている側面もある。
* **基本方針**：
  * ユーザー（病院側）にマスタ管理を任せることはサービスの提供価値を大きく損なうため現実的ではない。
  * **「重複データは発生する前提」** に立ち、不具合や運用負荷を減らす仕組みづくりを目指していく。

## 3. 重複医療機関データの課題と対応アプローチ

### 発生原因と現状
* **現状の件数**：Asanaで管理されているチケット上、同じ医療機関が別番号（別ID）で登録されてしまっている重複医療機関が **126件** 存在する。
* **発生メカニズム**：
  1. 医療機関マスタ（MIS）は厚生労働省の公開データをもとに月1回更新しているが、新規開業したクリニック等が公式マスタに反映・審査されるまでにはタイムラグが生じる。
  2. そのタイムラグの間に、**foro CRM** 上で「紹介元・紹介先となる新規クリニックをいち早く登録しておきたい」というニーズが発生し、手動で登録が行われる。
  3. 結果として、後から取り込まれる公式マスタのデータと手動登録データが二重に存在してしまう。

### 統合処理におけるリスクと技術的難易度
* **誤統合のリスク**：
  * 本来は別の医療機関であるものを誤って1つに統合してしまうリスクを避けるため、慎重なデータ名寄せ（確認作業）が必要となる。
* **DBテーブル統合の複雑さ**：
  * 重複する医療機関IDに紐づくテーブルは **20〜30個** に及ぶ。
  * 単純な `UPDATE` 処理だけでは統合できないテーブルが存在するため、手作業や慎重な判断が求められる。
  * *(※社内DB定義より補足：`foro` DBの `crm_medical_institution_phases` や `mis` DBの `medical_institution_specialties`、`ref_naviis` 等、`medicalInstitutionId` を含むユニーク制約が存在するテーブルが多いため、単純なID付け替えでは制約違反やデータ競合が発生する構造となっている)*

### 自動化・効率化に向けた技術的見解（Kyohei Yoshida）
* **同一施設の判定 vs 統合処理の切り分け**：
  * 「どの病院とどの病院が同一であるか」の判断自体は自動化が難しい。
  * 一方で、判断後の **データ統合処理（DB更新等）自体はバッチ化や半自動化の余地がある**。
* **重複データの自動検知**：
  * 現在はData Opsチームのメンバーが毎月のデータ登録・クレンジング作業の中で手動で重複を発見し、Asanaに蓄積している。
  * **MCPやAIツール** を活用すれば、Asanaにアクセスして重複データを自動的に検知・抽出する仕組みを構築することは理論上可能である。
