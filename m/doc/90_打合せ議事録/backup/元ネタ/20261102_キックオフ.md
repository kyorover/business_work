# 業務引き継ぎ・オンボーディング 要点まとめ

## 1. 全体方針・役割分担

* **最優先事項:** 既存SaaSプロダクト「foroシリーズ」（4つのうち1つ）の保守運用を1人で回せるようになること。

* **引き継ぎ計画:** 11月・12月をキャッチアップ期間とし、現在保守を担当している業務委託メンバー（新保氏・参画1年程度）から定期的な作業等を巻き取る。来月には自力で保守を回せる状態を目指す。

* **新規事業（AIDPC）への参画:** 既存SaaSの保守業務の空き時間を活用し、新規事業の追加保守や開発にも参加していく。年明け以降、開発時に最低限の対応ができるようにする。

* **チーム体制:**

  * 現在は新規事業専任1名、既存SaaS担当（新保氏）1名の体制。

  * 12月中にエンジニア2名が契約終了予定。

  * 新保氏は11月から新規事業の開発および保守へシフトする。

* **リリース予定:** 今月・来月あたりにプロダクトのリリースが予定されている。

## 2. 担当業務とタスク

**【直近のタスク】**

* **今週中目処:** まずは開発環境の構築を実施する（メダップコアサービス編は一通り完了済み）。

* **初期タスク:** foroの最初のタスクとして、システムへの「特記事項追加」の簡単な対応を行う。

* **今月末頃:** Railsのメジャーバージョンアップ対応（1〜2週間想定）を最初の案件として実施。新保氏にヒアリング・サポートを受けながら進める。

**【保守運用・定例業務】**

* 現状、既存SaaSに関しては新規開発の予定はなく、QA対応、パッチ対応、保守がメインとなる。

* 定期的なデータ投入や、月末の手動データ抽出などの業務がある。

* リファクタリングに伴うバグ（データ修正等）の緊急対応が発生する場合がある。

* Node.jsのEOL（来年4月末期限）対応については、新保氏が調査し、年明けに計画を立てて着手する（ボリューム次第で2人体制）。

## 3. 運用ルール・スケジュール

* **勤務形態・時間:** フルリモート（兵庫県から）。コアタイムは13:00〜15:00。

* **会議体:**

  * 夕方17:00から日次のデイリー打ち合わせ（foro_dev夕会）を実施（参加必須）。

  * 朝会は原則行わず、必要な場合のみ11時半に開催する。

* **タスク・進捗共有:**

  * Slackの `#foro_dev_daily_share` （および `#foro_dev`）チャンネルを使用。

  * 朝10時のリマインダーに合わせて「本日やること」を投稿し、後に「やった結果」を投稿する。

  * バックログ（Backlog）を用いてタスクを整理・管理する。

* **カレンダー運用:**

  * Googleカレンダーでデイリー打ち合わせやリリース予定を管理。

  * 運用カレンダーの確認が必須（手動でのデータ抽出業務などがあるため）。

  * 休日前日にはリリースを行わず、翌営業日（水曜等）に延期するルール。

* **コミュニケーション:** 質問やメンションは時間帯を気にせず行ってよい。技術的な詳細は新保氏に質問し、Slackやカレンダーで予定を入れて30分程度通話するルール。

* **その他:** 年末年始の営業日は別途山田氏から連絡がある。

## 4. 開発環境・インフラ・ツール

* **インフラ・認証:** インフラはすべてGCPで構築（権限設定済み）。認証部分のみAzure Active Directory B2Cを使用。

* **ドキュメント・設計:** 開発環境の情報はNotionで検索可能（検索ワード：「開発環境」など）。設計内容は主にFigmaに記載されている。

* **各種ツール:**

  * GitHub: リポジトリのクローン・開発実施。

  * 1Password: 環境変数や認証情報の管理に使用（Chrome拡張機能経由でアクティベーション済み）。

## 5. 端末利用・AIツール・事務手続き

* **貸与端末（MacBook）:**

  * 会社提供のメールアドレスを用いてAppleアカウントを作成して問題ない（実施済み）。

  * USBポートの利用（マウス・キーボード等の接続）も可能。

* **AIツールの利用とセキュリティ:**

  * CursorやClaude、Copilot等のAIツールの業務利用は可能。

  * **【禁止事項】** 患者名や患者IDなどの医療情報（カルテや診療内容など）の機密データをAIに入力することは厳重に禁止。

  * **【許可事項】** その他の文書や、GitHubなどのソースコードをAIに読ませることは問題なし（開発環境のセットアップ効率化等に併用可）。

* **AIツールの費用・経費精算:**

  * 個人のAI利用は問題なく、発生した費用は高額でなければ会社負担とする（参考：山田氏はCursorを利用し月3,000円程度の費用が発生）。

  * 月末の勤怠報告を送信するタイミングで、経費精算として提出する。

* **勤怠報告:**

  * ファインディ側のフォーマットで月末に報告し、承認を経て請求へ回す（経費精算のフォーマット指定は特になし）。
