## 1. 会議概要

* **日時**：2026年11月18日（水）10:29〜11:05（約35分）
* **参加者**：Yoshihisa Mihara（PdM）、Jun Yamada、Kyohei Yoshida
* **対象プロダクト**：**foro 入退院調整**（`acute-care-flow-web`／GW頃に初期リリース、9月に機能拡充を実施）
* **議題**：先行導入3病院からのフィードバック（VoC）共有、各機能の優先順位検討、および12月〜3月の開発スケジュール確認

## 2. 決定事項・開発スケジュール

### 全体スケジュールと方針
* **2026年12月（最優先）**：入退院機能の**セキュリティ対応をメイン・最優先**で実施する。
  * セキュリティ対応の負荷次第では、軽微な改修で体験が大きく向上する機能や文書作成の着手を年内に前倒し・並行実施できるか検討する。
* **2027年1月〜3月（年明け以降）**：セキュリティ対応完了後、**VoCに基づく機能拡張**を実施する。
* **優先実装の方針**：現行の紙業務からの完全移行（業務リプレース）に直結する**「印刷機能（相談連絡表・文書サマリー）」**を、細かな入力項目追加や検索機能よりも優先して実装する。
* **先行3病院への期待値調整**：セキュリティ優先により機能追加が少し遅れる可能性と、現行業務の完全移行の目安が年明けになる旨はすでに伝達済みであり、期待値コントロールができている。

## 3. 先行3病院からのフィードバック（VoC）とモックアップの状況

### 先行導入3病院と要望一覧の整理方法
* **先行3病院**：**麻生総合病院**、**霞ヶ関病院**、**ベルピアノ病院**
* **VoC要望一覧（3院統合エクセル）**：
  * 病院ごとに業務フローが異なるためフィードバックの濃度に差がある。
  * ミーティングの生ログ（議事録テキスト）を **Claude** に入力して構造化・整理したものを共有基準としている（エクセルのF・G・H列に対象病院を記載）。
  * 全体で三十数項目ある中から、相談一覧・入力項目・出力印刷・権限セキュリティなどに絞った**約20項目**を抽出して整理している。
  * AIが出力した優先度「高」は「3病院に共通する要望」を指しているが、3病院だけの傾向にすぎないため、メダップの方針として本当に優先すべきかは別途見極めが必要。

### モックアップの変遷（10月版 → 11月版）
* モックアップは **10月時点版**（Notionに掲載されているのはこちらのみ）と、その後の追加フィードバックを反映した **11月版（HTML版）** の2段階がある。
* **入力系統**は10月末時点でほぼ合格をもらっており完成形に近い。11月版ではタブ・画面構成の変更など**管理系の要望**が多く反映されている（10月と11月で大きな優先順位の軸自体は変わっていない）。

## 4. 個別機能・要望の優先度と議論内容

| 機能・要望 | 優先度（方向性） | 背景・現場ニーズと議論の要点 |
| :--- | :---: | :--- |
| **印刷機能・文書サマリー**<br>（相談連絡表／文書サマリー） | **高（最優先）** | 現行の紙業務をシステムへ完全移行するために**マスト**。細かな項目追加などの「便利になる系」機能より優先して対応する。詳細は下記参照。 |
| **入院／退院チームの画面切り替えスイッチ** | **高** | 入院チームと退院チームで利用する機能・画面が異なるため、タブやスイッチでスムーズに切り替えられるようにする必要がある。 |
| **紹介元医療機関の直接検索** | **中〜低** | 霞ヶ関病院など関東圏では登録病院数が60〜70施設（`acute_cf_referral_medical_institutions`）に達し、スクロール検索が煩わしいという声がある。ただし山田氏見解として、マストな要件・クリティカルな優先度ではない。 |
| **相談一覧の複数条件絞り込み（AND/OR検索）** | **低** | 現状は単一条件のみ。疾患グループや紹介元を組み合わせた絞り込みは、日常業務の現場担当者ではなく**管理職・幹部層（経営側）**や医師・看護師が過去データの傾向・総数を見る用途（頻度は半年に1回レベル）。<br>経営側にも使ってもらいたい意図はあるものの、1日の登録数が20人未満であり、初動の単一検索で10〜20件に絞れれば日常業務には十分なため優先度は低い。 |
| **電子カルテ向け出力（QRコード）** | **低** | 印刷・出力パターンの1つとして挙がっているが、三原氏より「急がなくてよい」との判断。 |

### 印刷機能・文書出力の詳細仕様方針
* **AIは使用せず**、システムに入力済みの項目をシンプルに整理して出力する。
* 相談連絡表と文書サマリーは**個別に印刷できる**ようにし、用途に応じて以下の通りページ・フォーマットを完全に切り分ける。
  1. **相談連絡表（入院受付表）**：入力のある項目のみを印刷可能。**患者への確認や院内回覧**に使用する。
  2. **文書サマリー**：**入院受け入れ評価向け**。シビアな（厳しい）機微情報が含まれうるため、患者向けにも使う相談連絡表とは**完全にページを分離**する。（※社内DB定義上も `acute_cf_patient_details` と `acute_cf_patient_sensitive_details` が分離されている）
  3. **電子カルテ向け出力（QRコード取り込み形式）**：今回は急がず後回しとする。

## 5. 要望管理・共有プロセスの改善

* **優先度の根拠とメダップ方針の明記**：
  * 現状のAI（Claude）による優先度記載は「会話の記録」にすぎず、一件ずつ三原氏の口頭説明がないと開発側で価値判断がしづらい。
  * 三原氏が優先度の列を見直し、「分析用で経営陣が半年に1回使うものであり、日常業務では使わない」といった**判断根拠とメダップとしての方針・見解**を一覧へ追記する。
* **Claude・要望一覧ファイルの共有**：
  * Claude上のファイル環境およびVoC要望一覧（3院統合エクセル等）に、山田氏・吉田氏を閲覧・編集権限で招待し、今後の要望管理やチャットでの確認に活用する。
