|  | refery |
| --- | --- |

| --- | --- | --- |

✅ **fnm のほうが保守的なので、再承認は不要。** ★**ただし一言は伝える。**

### 🔴🔴 B-1＋B-2 は、**間を空けずに続けて**実行する 🧑 小山

⚠️🔴 **理由＝`~/.zshrc` を書き換えると、別の Claude Code の Bash 実行にも効く**（★シェルがプロファイルから初期化されるため）。
🔴 **B-1 と B-2 の間に「fnm は有効だが node が1つも入っていない」窓ができる。** ★**その間に向こうが何か実行すると、node が見つからない可能性がある。**

**だから 事前に一声かけて、向こうを止めてから、下を一気に貼る。**

```bash
# ── B-1：fnm を入れて有効化
brew install fnm
cat >> ~/.zshrc <<'ZEOF'

# fnm（node のバージョン管理・2026-09-18 追加）
eval "$(fnm env --use-on-cd --version-file-strategy recursive --shell zsh)"
ZEOF
eval "$(fnm env --use-on-cd --version-file-strategy recursive --shell zsh)"

# 🔴 別を守るための「既定値」を置く
echo "25.9.0" > ~/.node-version

# ── B-2：2つとも入れて、デフォルトは今のまま
fnm install 22.23.1
fnm install 25.9.0        # 🔴 これが要る（★default は「入っている版」にしか付けられない）
fnm default 25.9.0        # 🔴 デフォルトは別に合わせて据え置き
```

---

✅ **貼り終えたらシェルを開き直します：**

```bash
exec zsh -l               # 開き直す
```

⚠️🔴🔴 **【2026-09-25 訂正】ここには「`~/.zshrc` はいま1行だけなので戻すのも簡単です」と書いてありました。**🔴**2つとも誤りです。**

| 書いてあったこと | 🔴**実測（2026-09-25 08:4x）** |
| --- | --- |
| **「いま1行だけ」** | 🔴**4行**（★`PATH` 1行＋`fnm` 2行＋別の `export` 2行） |
| **「戻すのも簡単です」** | 🔴🔴**簡単ではない**（★下の理由2つ） |

#### **🔴🔴 控え（`~/.zshrc.bak_20260918`）から戻してはいけない**

|  | mtime | 中身 |
| --- | --- | --- |
| **控え** | **2026-09-18 20:03** | 🔴**すでに `fnm` の行が入っている**（★「変更前」ではない）。**そして後から足した `export` 1本が無い** |
| **現在** | **2026-09-18 20:26** | **上記＋`export` 1本** |

🔴 **だから `cp` で戻すと、`fnm` は消えずに、関係のない `export` 1本だけが消える。** ★**控えがあることは、戻せることを意味しない。**

#### **✅ 本当の戻し方（★行を指定して消す。`cp` で上書きしない）**

```bash
cp ~/.zshrc "$HOME/.zshrc.bak_$(date +%Y%m%d_%H%M)"   # 🔴 まず「今」の控えを取る
sed -i '' '/^# fnm（node のバージョン管理・2026-09-18 追加）$/d' ~/.zshrc
sed -i '' '/^eval "\$(fnm env --use-on-cd --version-file-strategy recursive --shell zsh)"$/d' ~/.zshrc

```

⚠️🔴🔴 **ただし、これだけでは戻りきりません。「依頼が要る」ものが2つ残ります：**

| # | 残るもの | なぜ勝手に消せないか |
| --- | --- | --- |
| **1** | **`~/.node-version`** | 🔴**別の実行が `--version-file-strategy recursive` で拾っている。**✅**向こうが自前ファイルを置いた連絡の後に消す** |
| **2** | 🔴**`fnm install` で入れた node 本体** | 🔴🔴**`fnm` を外すと、別の実行の node 解決経路が変わる。**★**`brew` 側の node が残っているかを先に実測する** |

🎯 **型＝「入れるのは1コマンド、戻すのは依存の棚卸し」。** ★**共有ファイルに足したものは、足した側だけでは戻せない。**

### 🔴🔴 B-3. 検算＝**必ず refery を経由してから測る** 🧑 小山

### 🔴🔴 【2026-09-18 実測】なぜ2つの仕掛けが要るのか

**最初は `fnm env --use-on-cd` だけで試しました。** 🔴**戻りませんでした。**

```
cd ~/refery              → 22.23.1
cd ~/security-saas-mvp   → 🔴 22.23.1 のまま      ← 戻らない
cd ~                     → 🔴 22.23.1 のまま
```

⚠️ **次に `~/.node-version`（25.9.0）を置きました。** ★**`~` では戻るようになったが、`~/security-saas-mvp` ではまだ戻らなかった。**

🔴🔴 **原因＝fnm の既定は `--version-file-strategy local`＝「そのディレクトリだけ」を見る。親をたどらない。**

✅ **`recursive` にして解決。**

```
cd ~/refery              → 22.23.1   （自分の .node-version）
cd ~/security-saas-mvp   → 25.9.0    （親をたどって ~/.node-version）
cd ~                     → 25.9.0
```

🎯 **つまり 必要なのは2つセットです。**

| # |  |
| --- | --- |
| **1** | **`--version-file-strategy recursive`**（★親をたどらせる） |
| **2** | **`~/.node-version` に `25.9.0`**（★たどった先に置く既定値） |

⚠️🔴 **片方だけでは直りません**（★実測で2回外した）。

🔴 **`chpwd` フックなので、Claude Code の Bash（非対話）では発火しません。**

|  | node |

| **ターミナル（対話）** | **ディレクトリで切り替わる** |
| **Claude Code の Bash** | 🔴**常にデフォルトの 25.9.0** |

⚠️ **裏返し＝Code が `~/refery` でコマンドを打つと 25.9.0 で動く。** ★**明示が要る。**

```bash

```

### C-1. 🔴 OrbStack を起動 🧑 小山

⚠️🔴 **【2026-09-18 訂正】社内の手順書は「docker が手元の Mac に入っていない方は…」と書いていますが、

```
docker context        → orbstack（選択中）
```

★ **OrbStack は Docker Desktop の代替で、`docker` コマンドはそのまま使えます。**

```bash

```

✅ **検算**


**2026-09-18 に実際に出ました。** ★**OrbStack 自身がメッセージに直し方を書いています。**

```

This is usually caused by Migration Assistant changing its owner to root.
```

✅ **データは消えません**（★1.8GB がそのまま残る）。⚠️**`sudo` なので Mac のパスワードを聞かれます。**
